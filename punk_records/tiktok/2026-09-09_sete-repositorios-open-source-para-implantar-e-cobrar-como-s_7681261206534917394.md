# Sete repositórios open source para implantar e cobrar como serviço (com as licenças conferidas)

🔗 https://www.tiktok.com/@luisfernando_engdev/photo/7681261206534917394

## Resumo

O carrossel propõe o modelo mais antigo do software livre — pegar um projeto aberto, implantar, manter e cobrar pelo serviço, como a Red Hat fez — e lista sete repositórios com o valor que, segundo o autor, o cliente pagaria por cada um: um CRM agêntico (trycompai/crm), uma suíte de auditoria de SEU (every-app/open-seo), um monitor de mudanças em páginas (changedetection.io), um clonador de sites por IA (ai-website-cloner-template), um gerador de PowerPoint nativo a partir de documentos (ppt-master), um framework de scraping adaptativo (Scrapling) e um OCR de documentos (PaddleOCR). Os valores anunciados vão de R$ 20 mil a R$ 60 mil por implantação e são afirmação do post, sem qualquer contrato ou caso mostrado. A parte substantiva está na legenda: o autor diz ter conferido licença por licença — quatro MIT, dois Apache 2.0 e um BSD 3 — e alerta que permissivo não significa sem obrigação. Todas exigem manter o aviso de direito autoral junto do que você entrega, a Apache 2.0 obriga a declarar o que foi modificado, e a BSD 3 traz a cláusula em que mais gente tropeça: não usar o nome do projeto para promover o seu serviço. O post fecha com a pergunta que sustenta o preço, já que o cliente pode baixar o mesmo repositório de graça: o que se vende não é o código, é implantação em servidor que fica de pé, configuração para o caso dele, integração com o que já existe e alguém que atende quando quebra. Ele também recomenda separar implantação de manutenção em contrato, para o serviço não virar suporte infinito.

## Tópicos

- **Permissivo não é sem obrigação** — MIT, Apache 2.0 e BSD 3 liberam uso comercial, mas todas exigem manter o aviso de direito autoral junto da entrega.
- **Cláusulas que pegam** — Apache 2.0 obriga a declarar o que você modificou; BSD 3 proíbe usar o nome do projeto para promover o seu serviço.
- **O que sustenta o preço** — O cliente pode baixar o repositório de graça; o que se cobra é implantação estável, configuração, integração e atendimento quando quebrar.
- **Separar implantação de manutenção** — Contratar as duas coisas juntas transforma o projeto em suporte infinito sem preço definido.
- **Os valores anunciados são alegação** — Os R$ 20 mil a R$ 60 mil por projeto aparecem sem contrato, caso ou cliente que os comprove.

## Ferramentas citadas

- **trycompai/crm**: CRM open source pensado para agentes de IA; licença MIT
- **every-app/open-seo**: auditoria de site, ranking e pesquisa de palavra-chave, no lugar de Semrush/Ahrefs; MIT
- **dgtlmoon/changedetection.io**: monitora qualquer página e avisa quando muda — vendável como vigilância de preço e concorrência; Apache 2.0
- **JCodesMore/ai-website-cloner-template**: reconstrói o site de um prospect como template funcional, para entrar na reunião com a demo pronta; MIT
- **hugohe3/ppt-master**: transforma documento ou tema em PowerPoint nativo com gráficos e animações; MIT
- **D4Vinci/Scrapling**: scraper adaptativo que sobrevive a mudança de layout, vendido como lista de leads que se reabastece; BSD 3
- **PaddlePaddle/PaddleOCR**: converte PDF e escaneamento em dado estruturado — faturas, contratos, fichas; Apache 2.0

## Pontos-chave

- O modelo é o da Red Hat: o software é livre, o serviço em volta é o produto.
- Licenças conferidas pelo autor: quatro MIT, dois Apache 2.0, um BSD 3 — nenhuma proíbe uso comercial.
- Todas as três licenças exigem manter o aviso de direito autoral no que você entrega ao cliente.
- Apache 2.0 exige declarar as modificações que você fez.
- BSD 3 proíbe usar o nome do projeto para promover o seu serviço — o erro mais comum na hora de vender.
- O preço se sustenta em implantação, configuração, integração e atendimento, nunca no código.
- Separar implantação de manutenção no contrato evita suporte infinito.
- Os valores de R$ 20 mil a R$ 60 mil por projeto são afirmação do post, sem prova.

## Como aplicar

É a resposta prática para o que Fernando vende depois da landing: em vez de construir do zero, implantar uma ferramenta aberta no servidor do cliente e cobrar por implantação, configuração e manutenção — changedetection.io e PaddleOCR são os dois mais vendáveis a negócio local. A parte de licença é o que precisa entrar no contrato antes de qualquer entrega: manter o aviso de copyright, e nunca escrever o nome do projeto BSD 3 no material de venda.
