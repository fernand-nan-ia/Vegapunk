# Pilha de ferramentas para montar um MVP de SaaS: Stitch, Claude, 21st.dev, Search Console, UAZAPI, Oracle e Supabase

🔗 https://www.tiktok.com/@ivesgabriell/photo/7673143692844141832

## Resumo

Carrossel de Ives Gabriel listando a rota de ferramentas que ele usa para levar um site ou SaaS do zero ao MVP. Começa com Google Stitch para prototipar as telas iniciais. O desenvolvimento fica com o Claude, e ele propõe uma orquestração explícita entre modelos: Fable para planejamento e revisão final de segurança, Opus 4.8 como construtor. Para o front-end não ficar com cara de IA, indica Higgsfield ou 21st.dev como fonte de componentes. Google Search Console entra para criação de perfil e demanda orgânica via SEO. UAZAPI cuida do disparo de mensagem no WhatsApp após o cadastro. A Oracle, na camada de infraestrutura, hospeda o back-end. O banco fica no Supabase, com a ressalva de usar o Claude como apoio para quem não domina SQL. Como bônus, cita ASAAS, Stripe e AbacatePay como gateways de pagamento — mas com um conselho contraintuitivo: nos primeiros 50 clientes, fazer o sucesso do cliente inteiro no WhatsApp, um a um, para garantir experiência e evitar que a pessoa fique só um mês. Deixa claro que essa é a rota do MVP, a primeira versão, e que o nível de desenvolvimento sobe depois.

## Tópicos

- **Prototipação** — Google Stitch para as telas iniciais antes de qualquer código.
- **Orquestração de modelos** — Fable para planejamento e revisão final de segurança; Opus 4.8 como construtor — papéis separados, não um modelo para tudo.
- **Front-end sem cara de IA** — Higgsfield ou 21st.dev como fonte de componentes prontos.
- **Aquisição e retenção** — Search Console para demanda orgânica; UAZAPI para mensagem no WhatsApp após o cadastro.
- **Infra e dados** — Oracle hospedando o back-end e Supabase como banco, com o Claude apoiando quem não domina SQL.
- **Pagamento e sucesso do cliente** — ASAAS, Stripe ou AbacatePay — mas nos 50 primeiros clientes o atendimento é manual, no WhatsApp.

## Ferramentas citadas

- **Google Stitch**: prototipação das telas iniciais
- **Claude**: desenvolvimento, com Fable planejando e revisando segurança e Opus construindo
- **21st.dev / Higgsfield**: componentes de front-end para não ficar com cara de IA
- **Google Search Console**: perfil e demanda orgânica por SEO
- **UAZAPI**: disparo de mensagem no WhatsApp pós-cadastro
- **Oracle Linux**: hospedagem do back-end
- **Supabase**: banco de dados
- **ASAAS / Stripe / AbacatePay**: gateways de pagamento citados como bônus

## Pontos-chave

- Separar papéis entre modelos: um planeja e revisa segurança, outro constrói — não usar o mesmo para tudo
- Prototipar telas ANTES de gerar código reduz retrabalho
- Biblioteca de componentes é a resposta prática ao problema de 'cara de IA' no front
- Nos primeiros 50 clientes, sucesso do cliente manual no WhatsApp — evita churn de um mês
- Rota declaradamente de MVP: o nível de desenvolvimento sobe depois
- Supabase com Claude de apoio é o caminho sugerido para quem não domina SQL
- Carrossel promocional: fecha com convite para comunidade e link na bio

## Como aplicar

A lista de ferramentas vale como cardápio, não como receita — mas duas ideias se aplicam direto ao SaaS pessoal: separar o modelo que planeja/revisa do que constrói (é exatamente a divisão Stella-story/Atlas-develop que o Vegapunk já pratica), e atender os primeiros clientes um a um antes de automatizar. O Supabase já aparece em outros itens do vault como escolha recorrente.
