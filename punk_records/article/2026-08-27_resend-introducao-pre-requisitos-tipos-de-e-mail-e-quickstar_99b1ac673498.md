# Resend — introdução: pré-requisitos, tipos de e-mail e quickstarts por linguagem

🔗 https://resend.com/docs/introduction

## Resumo

Página inicial da documentação do Resend. Para começar são necessários um domínio próprio verificado e uma chave de API. Dois tipos de envio: e-mails transacionais (personalizados, disparados por eventos) e campanhas de marketing (Broadcasts em massa para uma lista de contatos). Há quickstarts para Node.js, Next.js, Express, PHP, Laravel, Python, Ruby, Rails, Go, Rust, Elixir, Java, .NET e CLI. A documentação inteira está disponível em llms.txt e llms-full.txt (formatos para LLMs). Seções: Emails, Domains, Webhooks.

## Tópicos

- **Pré-requisitos** — Domínio próprio verificado e API key.
- **Dois modos** — Transacional por evento; Broadcasts para listas.
- **Quickstarts** — Node, Next, Express, PHP, Laravel, Python, Ruby, Rails, Go, Rust, Elixir, Java, .NET, CLI.
- **Docs para LLM** — llms.txt e llms-full.txt.

## Pontos-chave

- Sem domínio próprio verificado não se envia nada — domínio vem antes do código.
- Python tem SDK oficial e quickstart.
- llms-full.txt permite dar a documentação inteira a um agente de uma vez.

## Como aplicar

Antes de codar: verificar o domínio do SaaS (subdomínio) no Resend; usar o quickstart Python.

## 🔧 Atlas diz

Peça pequena, mas com um parafuso escondido: llms-full.txt. Quando eu for soldar o envio no SaaS, jogo esse arquivo inteiro no contexto e paro de adivinhar parâmetro. Passo 0 continua sendo domínio verificado — sem ele, nada sai.
