# Resend — exemplos de código por framework (Next.js, Express, Hono, FastAPI/Flask/Django, Rails, Go…) e por recurso

🔗 https://resend.com/docs/examples

## Resumo

Repositório de exemplos do Resend organizado por framework — Next.js (TS/JS), Express 5, Hono, Bun, Remix, Nuxt 3, SvelteKit, Astro, RedwoodJS, TanStack Start, PHP (Slim/Symfony), Laravel 11, Python (Flask, FastAPI, Django), Ruby (Sinatra/Rails), Go (Chi/Gin), Java (Javalin/Spring Boot), .NET, Rust (Axum), Elixir (Phoenix) — e por recurso: envio básico, anexos, imagens inline (CID), React Email, templates hospedados, agendamento, formulário de contato com lote via Server Actions, double opt-in, webhooks inbound, evitar threading no Gmail, audiences, domínios, automations e autenticação por e-mail com Better Auth.

## Tópicos

- **Frameworks** — Next, Express, Hono, Bun, Remix, Nuxt, SvelteKit, Astro, Redwood, TanStack, PHP, Laravel, Python, Ruby, Go, Java, .NET, Rust, Elixir.
- **Recursos** — Send, attachments, CID, React Email, templates, scheduling, contact form, double opt-in, inbound, threading, audiences, domains, automations, Better Auth.

## Pontos-chave

- Há exemplo FastAPI/Flask/Django — o caminho Python do SaaS já está escrito.
- Double opt-in e formulário de contato são os dois casos do site do cliente.
- Better Auth mostra login por e-mail (magic link) com Resend.

## Como aplicar

Copiar o exemplo Python (FastAPI) para o SaaS e o de formulário de contato/double opt-in para o site do cliente.

## 🔧 Atlas diz

Exemplo pronto é peça usinada: não se reinventa. FastAPI para o SaaS, formulário de contato para o cliente, magic link com Better Auth se o Edison quiser login sem senha. Quando o Fernando disser 'faz', eu começo por aqui.
